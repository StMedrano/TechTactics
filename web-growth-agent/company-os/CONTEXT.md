# Context

Context is the information a worker needs for the current run. It is not long-term company memory.

## Assemble the smallest useful context

For prospecting/sales work, include only what is relevant:
- Lead/business record
- Market/category
- Website URL or no-website status
- Recorded audit evidence
- Current pipeline state
- Package/pricing rules
- Outreach history
- Approval state
- Next action
- Relevant recent notes

For build/delivery work, include:
- Client/project record
- Approved scope
- Brand/content assets
- Site/repository state
- Integrations
- Current milestone/blockers
- Client decisions
- Deployment/environment state
- Approval status

## Context rule

Do not dump the entire company history into every task. Pull durable facts from `MEMORY.md` and decision rationale from `DECISIONS.md`, then combine them with the current work record.
